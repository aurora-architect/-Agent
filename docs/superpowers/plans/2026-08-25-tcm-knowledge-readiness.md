# TCM Knowledge Governance and Readiness Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first independently testable subsystem for the TCM professional avatar: governed knowledge assets and a fail-closed readiness gate that must pass before autonomous follow-up questions or AI drafts can be enabled.

**Architecture:** A TypeScript domain package owns knowledge states, validation, review transitions, and readiness decisions. A Fastify API exposes write and read operations; PostgreSQL stores immutable versions and audit events through Drizzle. No patient business record enters this subsystem, and no model-generated medical conclusion can become an approved asset.

**Tech Stack:** Node.js 22, TypeScript 5.7, pnpm 10, Fastify 5, Zod 3, PostgreSQL 16, Drizzle ORM 0.38, Vitest 3

**Spec:** `docs/prd/中医数字伴侣长期调理复诊最小闭环产品需求文档.md`

## Global Constraints

- Implement only P0 knowledge governance and `P0-F001C`; patient records, diagnosis, prescriptions, treatment changes, follow-up decisions, and outbound medical messages are outside this plan.
- The readiness gate fails closed when a required asset is missing, unreviewed, expired, unauthorized, or lacks provenance.
- Every approved asset has owner, source, version, scope, permission, review status, reviewer, reviewed time, and validity interval.
- Candidate content never participates in runtime retrieval.
- Patient-identifiable content is rejected before persistence in this knowledge subsystem.
- Every state change appends an audit event; updates never overwrite previous approved versions.
- All timestamps are UTC ISO 8601 values; identifiers are UUID v7 values generated by the API.
