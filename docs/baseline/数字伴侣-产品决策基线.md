# 数字伴侣产品决策基线

本文件记录已经明确、会约束当前产品文档和日程一期研发的决策。与历史描述冲突时，以本文件为准；待确认事项不得被写成当前实现或正式承诺。

|编号|主题|当前决策|状态|对需求的约束|
|---|---|---|---|---|
|BL-001|产品定位|数字伴侣围绕个人事务处理、专业沉淀和受控的对外服务放大用户能力，不以制造情感依赖为目标|已确认|禁止以虚拟恋爱、情感依赖作为核心机制|
|BL-002|日程类型|一期仅包含出差、会议、拜访、宴请、纪念日、就医、学习、家庭八类；“行程/出行”不是第九类|已确认|所有日程枚举、筛选、语料和测试必须使用八类合法值|
|BL-003|日程意图|日程意图识别统一由后端 ALITA AI 承担|已确认|客户端不得并行维护另一套日程意图分类器|
|BL-004|参与者|一期参与者为非结构化文本；卡片展示原文本；不生成 `participant_ids`，不匹配身份，不邀请、不共享|已确认|参与者文本不构成读取联系人资料的授权|
|BL-005|会议能力|一期不提供在线会议、拉会、会议室、会议链接和第三方会议数据投喂|已确认|相关字段、入口和验收不得进入一期|
|BL-006|时区|使用用户手机系统时区作为解析上下文，不提供用户编辑日程时区|已确认|时区上下文属于 P0 数据正确性门禁|
|BL-007|普通创建确认|除深度研究流程外，普通自然语言创建日程不弹结构化确认卡|已确认|信息充分时直接创建并回显；阻断信息缺失时只追问必要信息|
|BL-008|自然语言修改|修改已有事务后必须展示变更确认卡；变更先应用，用户再确认本次修改|已确认|卡片必须有确认按钮、整卡入口和编辑按钮；确认不重复 Update；整卡和编辑进入当前日程草稿；不提供撤销按钮、撤销状态或撤销接口|
|BL-009|AI 建议|符合展示条件的单条 AI 回复展示 3 条高价值、可点击建议；不足 3 条则不展示|已确认|点击建议后，以用户身份发送对话气泡并重新进入主 Agent|
|BL-010|待办流转|LLM 先判断待办可能归属的一类或多类八类事务，再由主 Agent 在对话中推动，用户决定后才创建后续事务对象|已确认|不得把提取出的待办自动落为正式日程、提醒或其他事务；底层对象归属仍待讨论|
|BL-011|提醒边界|常规提醒服务与主动提醒/主动服务触达是两种不同能力|已确认|分别定义触发、owner、状态、去重、失败和验收|
|BL-012|登录|一期只支持输入手机号并完成验证码校验；不支持运营商一键登录|已确认|删除一键登录页面、SDK 和测试要求|
|BL-013|账号操作|一期不支持账号切换；支持账号登出|已确认|登录态失效不得通过“切换账号”验收；登出与账号注销分开|
|BL-014|年龄|仅年满 18 周岁的用户可注册和使用|已确认|不得出现 14 周岁口径|
|BL-015|专业分身身份|客户/好友看到的发送者身份是用户；AI 生成回复需作标记，准确标记方案待政策和竞品研究后决策|部分确认|不得把“发送者显示为专业分身”作为一期验收；自动回复范围在标记方案确定前不得放行|
|BL-016|客户端导航|当前交互基线不采用底部导航|已确认|不得把底部 Tab 当作正式路由前提|
|BL-017|记忆写入|AI 推断内容不能直接作为用户事实写入长期记忆；敏感内容需要授权、可纠正、可删除|产品约束|日程一期优先生成候选或草稿，不承诺自动沉淀敏感内容|
|BL-018|实现证据|没有运行代码、接口 Schema 或联调日志支持的技术陈述不属于“当前实现”|证据规则|统一标记为目标需求或待研发确认|
|BL-019|出差闭环|出差主动服务必须形成“前置预判+主动服务+事后记录”完整闭环，不能只上线单点能力并宣称闭环完成|已确认|出差专项开放需同时通过天气、活动、交通建议、行程、清单、背景、总结、费用和人物沉淀最低门禁|
|BL-020|出差判定|出差是跨城市的日程；飞机和高铁是主要出行建议候选|已确认/偏好待验证|同城场景需澄清；不能新增“行程/出行”日程类型；飞机/高铁偏好需数据验证|
|BL-021|出差人物来源|关键人物沉淀必须保留清楚归属和来源，来源包含“YYYY年MM月DD日+出差+标题”|已确认|一期参与者仍是文本，不得跳过Memory实际机制直接创建确定联系人身份|
|BL-022|主 Agent 与专业能力隔离|主 Agent 拥有专业能力的控制权但默认不读取内容；只知道子分身存在、能力清单和运行状态，并通过接口路由。只有主用户主动调阅自己的专业能力或患者任务时，才可授予一次有范围、有时效、可撤销、可审计的读取权限|已确认|主 Agent 不得默认读取子分身专业记忆、患者服务内容或知识库正文；不得因路由结果写入主 Agent 长期记忆；调度传递任务引用和授权凭证，不复制专业内容|
|BL-023|个人事务 8 类范围|日程、出行、创意、重要时刻、个人知识、财务管理、定时事务、健康管理是产品能力版图，不表示 8 类在一期同时达到完整成熟度|已确认|每类进入版本前须单独冻结对象、范围、依赖和验收；禁止把能力版图直接转成一期全量交付承诺|
|BL-024|L2 结构化草稿|L2 表示意图明确但仍缺确认或关键字段时形成的对象草稿或补全卡；草稿尚未生效、尚未发送且无外部副作用|已确认语义/实现待专项|L2 升级到 L3/L4 前必须完成字段、权限和确认门禁；草稿生命周期、存储和清理规则待权限专项|
|BL-025|登录注册入口|登录与注册对用户统一表现为手机号验证；新老账号及是否需要配置由服务端判断|已确认|前端不得要求用户先选择登录或注册，不得通过错误文案泄露手机号是否已注册，不得用设备首次启动代替新账号判断|
|BL-026|首次个性化|用户资料与伴侣配置当前全部可跳过；页面展示字段不等于必填|已确认|称呼、生日、职业、性别、头像、伴侣名称、语气、详略、排版和主动程度不得仅因出现在高保真中升级为注册门槛；跳过后使用版本化默认值或明确空值|
|BL-027|初始化与首页交接|初始化状态必须真实、可恢复且幂等；只有非关键任务失败才允许稍后处理|产品约束/实现待专项|关键账号、会话或配置未完成时不得进入首页；进度不可伪造；重试不得重复创建账号、会话、配置或初始化任务|
|BL-028|系统权限|协议同意、年龄确认、账号认证和系统权限授权相互独立；通知等权限在首页真实能力场景中触发|已确认|首次引导不得集中申请通知、麦克风、通讯录、日历、定位等权限；拒绝后保留不依赖权限的核心能力；解释层不得伪装系统授权结果|
|BL-029|验证码安全参数|验证码长度、有效期、重发冷却和频控由认证服务配置并执行|已确认边界|客户端不得硬编码6位、5分钟、60秒、每日10次等历史样例；不得保存验证码、写入普通日志或交给 AI 处理|
|BL-030|设计证据状态|Figma `5980:26516`“高保真（7.20-7.）”是未敲定设计输入，不是正式产品或实现真值|证据规则|可用于证明页面覆盖和交互意图；与产品定义、基线或专项 PRD 冲突时必须退回设计，不得直接改写基线|
|BL-031|一期全天日程|一期开放单日全天日程；跨天全天和其他跨天日程后置|已确认|`all_day=true`时开始/结束时间为空、结束日期等于开始日期；不得用00:00—23:59伪造；仅有日期但未明确全天时需澄清|
|BL-032|并发修改|开发采用字段级最后写入生效；任意客户端版本均可修改，同字段以最后成功写入为准，不同字段分别保留|已确认研发说明|版本用于顺序、审计、卡片和提醒派生关系，不作为普通修改冲突门禁；禁止旧快照全量覆盖当前对象|
|BL-033|笔记用于专业服务|不在启用专业分身时授权整个知识库；用户对单篇笔记点击一次“用于专业服务”，即明确允许专业分身使用当前笔记。笔记未在知识库时可同时建立收录关系，已在知识库时只增加当前笔记的专业服务使用许可|已确认|普通知识库笔记默认不可用于对外服务；点击只影响当前笔记，不扩大到同库其他内容；笔记修改后知识库展示同一份最新正文，更新后的AI可用性需重新判断|
|BL-034|知识库收录|保存笔记不自动建立用户知识库收录关系；用户手动加入或确认AI的非阻塞收录建议后才收录|已确认|普通保存流程不得出现阻断式收录确认；未经用户明确操作的自动收录次数必须为0；AI类型识别不构成收录授权|
|BL-035|知识内容模型|笔记是用户维护的唯一正文；知识库只建立收录关系，不复制第二份正文，也不设置用户必须逐条审核的知识草稿|已确认|从笔记或知识库入口编辑均更新同一内容；系统内部解析、来源、时效、冲突和风险状态不得变成用户必填治理流程|
|BL-036|本人使用与对外服务分权|数字伴侣可在产品隐私规则允许的范围内使用用户已明确收录且当前可用的内容帮助本人；专业分身对外使用仍需当前单篇笔记的独立许可|已确认|知识库收录、本人使用和专业服务许可是不同范围；不得因内容相关、启用分身或同属一个知识库自动扩大对外权限|
|BL-037|AI草稿采用与服务结果|专业分身先生成尚未发送的AI草稿；用户查看或编辑不发送，点击“采用”即向明确客户发送一次；发送成功不等于真实服务完成|已确认|采用操作必须幂等并展示真实发送状态；失败或结果不明不得记成功；真实服务结果只来自用户反馈或未来获准渠道，不由AI推断|
|BL-038|知识库MVP放行顺序|先通过知识基础闸门，再灰度单篇许可的专业服务闭环，最后才扩展内容来源、知识库数量和复杂治理能力|已确认|基础查找、来源、权限、删除和异常未通过前不得开放专业服务；专业服务边界未通过前不得扩大文件、图片、公众号、多库、自动回复或外部渠道|

## 待决策事项

|编号|主题|当前分歧|进入开发前的默认处理|
|---|---|---|---|
|OD-001|日程与统一事务对象|尚无运行代码和接口证据证明继承、复用或独立关系|产品使用“日程对象”描述；技术对象关系标记待研发确认|
|OD-002|提醒模型|提醒是属性、子对象还是独立调度对象尚未确认|产品定义用户规则；Schema 与 owner 不作假设|
|OD-003|P0 多级提醒|资料中存在“单次提醒 P0”和“当天/前一天/当周 P0”两种范围|本修订版采用用户最新补充：多级提醒进入 P0；研发需确认数据模型与调度成本|
|OD-004|删除/取消/完成|当前接口和状态枚举未证实能否拆分|产品语义分开；接口落地前不得伪造状态值|
|OD-005|账号注销|只确认一期支持账号登出，未确认注销账户流程|从一期范围移除，另立账号产品决策|
|OD-006|AI 回复标记|需要标记，但展示位置、文案、覆盖自动回复或草稿等范围未定|专业分身自动回复不作为本期放行项|
|OD-007|双入口策略持久化|联系人详情是单客户长期设置入口；客户对话页是即时切换入口。即时切换是否覆盖长期设置、作用到何时、如何恢复整体策略及如何反馈全局变更尚未确认|未决前，对话页切换不得静默覆盖联系人详情的持久化设置；进入开发前须冻结策略来源、作用域、版本和同步协议|
|OD-008|18+验证与存证|18+ 阈值已确认，但资格验证方式、边界日期、最小存证和地区规则未确认|未决前不得收集未经评审的身份证明，也不得仅凭前端勾选宣称合规完成；未满足资格不得创建正式账号或业务对象|
|OD-009|协议确认关系|启动协议确认、登录页协议展示、登录前主体绑定和账号创建后迁移规则未完全冻结|不得重复诱导确认；协议内容不可读时不得同意；服务端记录版本、主体、时间和结果|
|OD-010|初始化降级|初始化任务的关键/非关键分类以及“稍后再试”后可用范围未确认|账号、会话、安全存储等关键任务失败时停留恢复页；仅可后补任务允许进入有限可用首页|
|OD-011|个性化默认配置|个性化字段均可跳过已确认，具体系统默认名称、枚举、长度、敏感词和迁移策略未冻结|使用版本化配置；不得使用未经确认的“主人/小慧”等默认值，不得把系统默认伪装成用户选择|
