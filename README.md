# 中医数字伴侣 Agent

> [!WARNING]
> 本仓库目前处于产品方案与受控验证阶段，不是可直接提供诊断、处方或治疗建议的生产医疗系统。辨证、诊断、治疗方案、复诊建议和正式发送均由具备相应资质的医生完成。

面向高负荷独立执业中医的专业数字分身方案，聚焦“长期调理患者复诊前的信息收集与状态回顾”。

## 当前状态

- 文档版本：PRD v0.5
- 阶段：产品方案、原型与受控灰度准备
- 实施状态：尚未达到生产发布条件
- 核心原则：先治理知识，再启用专业分身；先验证最小闭环，再扩大范围

## 核心闭环

```text
创建但暂不启用中医专业分身
→ 建设并审核 P0 最小知识切片
→ 通过知识就绪门禁
→ 建立医生—患者授权关系
→ Agent 收集复诊任务缺失事实
→ 医生完成医学判断
→ Agent 依据医生确认内容生成未发送草稿
→ 医生确认并主动发送
→ 保存业务状态与审计记录
```

## 产品边界

- 专业分身只收集当前任务缺失的事实、调用获权内容并生成未发送草稿。
- 不自动诊断、辨证、开方、调整治疗方案或决定是否复诊。
- 患者原话、病历、报告、舌象和诊疗轮次属于业务记录，不自动进入知识库。
- 业务记录只有经过授权、脱敏、分类和人工审核后，才能成为正式知识或专业能力。
- 知识、能力、记忆和业务记录必须隔离管理并全程可审计。

## 发布阻断

当前仍有患者授权、医疗安全降级、数据留存与删除、知识责任人、评测阈值等 P0 阻断项。详见 PRD 的“P0 发布阻断项”章节；这些问题关闭前，不应宣称产品具备诊疗或生产发布能力。
